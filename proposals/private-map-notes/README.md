# 일정·지도 개인 메모 검토안

일정 ID별 개인 메모와 지도 마커를 추가했습니다. 현재 입장 안내 페이지는 변경하지 않습니다. 이 PR을 병합해도 운영 사이트에 기능이 자동으로 반영되지는 않습니다.

## 변경 사항

- 일정·일차별 개인 메모 작성, 수정, 삭제와 기기 자동 저장
- 메모가 있는 장소에 지도 마커 표시, 클릭하면 포스트잇형 편집 창
- 같은 장소의 일정은 마커만 묶고 메모 본문은 일정별로 구분
- 오프라인 작성, 계정 전환 시 가리기, 저장 실패 경고, 다른 탭의 변경 반영
- 보호자·게시판·교사 열람·인쇄·공개 안내판과 분리

현재는 계정별로 구분한 **기기 저장**입니다. DB 동기화·백업은 없고 공용 기기에서 개발자 도구로 읽힐 수 있으므로 민감한 정보를 적지 않아야 합니다. 교사의 계정 구분은 현재 API에 고유 ID가 없어 표시 이름을 사용합니다. 서버 연결 시 고유 사용자 ID로 교체해야 합니다.

## 파일과 적용

- `source/`: 새 화면·데이터 규칙·테스트·상세 안내. 실제 앱의 대응 경로로 옮깁니다. 검토용 `source/package.json`은 순수 데이터 테스트용이며 실제 앱에 덮어쓰지 않습니다.
- `integration.patch`: 기존 화면·저장소·빌드 검사·테스트 명령을 연결하는 수정분만 포함합니다.
- [상세 안내](source/docs/PRIVATE_NOTES.md): 저장 구조, 제약, 운영 적용과 서버 연결 방법.
- [변경 요약](CHANGES.md): 검증 결과와 남은 확인 사항.

원본 앱 기준은 `c7fa94aa7f06f75a7b17cd315d2dd751cc4acd48`, 구현 커밋은 `1a79db90cc2cc91c4693315035c39bea5b4e2f7d`입니다. 기준 앱에는 게시판 구현이 포함되어 있으므로 [게시판 PR #1](https://github.com/shinnanchanguk/gbshs-usa-2026/pull/1)의 연결 코드가 아직 없으면 그 차이도 대조해야 합니다. 이 PR에는 게시판 코드나 이전 안내 자료를 다시 포함하지 않았습니다.

운영 앱 담당자가 실제 소스의 별도 브랜치에서 `source/`를 대조한 뒤 `git apply --check <패치 경로>`를 실행합니다. 충돌은 수동으로 이식합니다. 현재 입장 안내 저장소에는 패치를 적용하지 않습니다. 적용 후 상세 안내의 전체 검사와 실제 로그인 계정 테스트를 실행해야 합니다.

이 검토안 자체에서는 Node 22.13 이상으로 `npm test --prefix proposals/private-map-notes/source`를 실행할 수 있습니다. 화면 검사·전체 빌드는 실제 앱 소스가 필요합니다. 운영 계정, 운영 DB, 명단·사진·좌석·객실 자료, 로컬 미리보기 로그인 파일은 포함하지 않았습니다. main 병합과 운영 배포는 하지 않습니다.
