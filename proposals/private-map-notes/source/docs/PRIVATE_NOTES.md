# 일정·지도 개인 메모

## 구현 범위

- 로그인한 학생·교사의 각 일정과 일차에 `메모 남기기` 버튼을 제공한다.
- 일정의 기존 `pageKey`를 그대로 사용한다. 일정 사실·ID·좌표는 변경하지 않는다.
- 최대 1,000자의 텍스트를 입력 즉시 기기에 저장한다. 앱을 열어 둔 상태라면 인터넷 없이도 처음 메모를 열어 작성할 수 있다.
- 좌표가 있는 일정의 메모는 해당 일차의 지도에 표시한다. 마커를 누르면 메모 편집 창이 열린다.
- 같은 일차·좌표의 일정은 마커만 묶는다. 메모 본문은 일정별로 따로 저장하며 선택 목록으로 전환한다.
- 장소 없는 일정·항공 일정·일차 전체에도 메모를 쓸 수 있다. 임의 좌표나 비행 경로에는 마커를 만들지 않는다.
- 수정·삭제, 다른 탭의 변경 반영, 저장 실패 경고, 키보드 초점 복귀를 지원한다.

드래그해서 임의 위치에 포스트잇을 놓는 기능, 사진 첨부, 게시판 공유, 서버 저장은 이번 범위에 없다. 포스트잇 느낌은 편집 창에만 절제해서 적용했다.

## 저장과 접근

저장소는 `usa2026:private-notes:v1` localStorage다. 형식은 다음과 같다.

```ts
type PrivateNote = {
  owner: string
  pageKey: string
  text: string
  updatedAt: string
}
type PrivateNoteBook = { version: 1; entries: PrivateNote[] }
```

- 학생은 ZUDO 세션의 학번으로 구분한다. 표시 이름이 바뀌어도 같은 메모를 읽는다.
- 현재 세션 응답에는 교사 고유 ID가 없어 교사는 정규화한 표시 이름으로 구분한다. 동명이인·이름 변경 가능성이 있으므로 서버 연결 시 반드시 고유 사용자 ID로 교체해야 한다.
- ZUDO 세션이 유효하고 `fromZudo` 프로필인 경우에만 버튼을 표시한다. 보호자·로그아웃·만료 세션에는 표시하지 않는다. 입장 PIN으로만 들어온 익명 기기에서는 활성화하지 않는다.
- 학생의 메모를 교사·보호자 화면, 기존 느낀 점·출석·게시판·사진·보고서로 전달하지 않는다.
- 공개 사전 안내판은 이 저장소를 읽지 않는다. 인쇄에서도 개인 메모를 숨긴다.
- 지도에는 일정 ID와 기존 장소 좌표만 사용한다. 메모 본문은 외부 지도 요청이나 GeoJSON에 포함하지 않는다.
- 저장 공간 부족·브라우저 저장 차단 시 메모리에서 입력을 유지하되 저장 완료로 안내하지 않는다. 실패한 변경은 새로고침·탭 종료 시 사라질 수 있다.

**한계:** 기기 저장은 암호화된 서버 권한 검증이 아니다. 같은 브라우저를 쓰는 사람이 개발자 도구로 저장값을 읽을 수 있고, 로그아웃해도 메모는 삭제하지 않는다. 공용 기기에 민감한 정보를 적지 말아야 한다. 브라우저 데이터 삭제·기기 변경 시 복구·동기화가 없으며, 동시 편집은 마지막 저장값이 우선한다. 앱 전체의 오프라인 최초 설치·지도 타일 캐시를 새로 보장하지는 않는다.

## 코드 위치

- `src/lib/privateNoteModel.ts`: 검증, 계정 구분, 일정별 저장, 장소별 마커 묶음의 순수 규칙.
- `src/lib/repo.ts`: 저장 방식의 경계인 `usePrivateNotes`.
- `src/lib/storage.ts`: 저장 성공 여부와 다른 탭의 변경 반영.
- `src/features/notes/`: 공유 상태, 일정 버튼, 편집 창, MapLibre 마커, 스타일.
- `src/app/Shell.tsx`, `src/features/page/`, `src/features/map/TripMap.tsx`: 기존 화면의 연결 지점.
- `scripts/check-guide.mjs`: 공개 빌드에 개인 메모 저장 코드가 들어가면 실패한다.

## 적용 전제

구현 기준은 보관된 앱 소스 `c7fa94aa7f06f75a7b17cd315d2dd751cc4acd48`이다. 로컬 기능 브랜치는 `codex/private-map-notes`다. 현재 협업 저장소의 `main`은 운영 ZUDO로 연결하는 진입 페이지만 포함하므로 이 패치를 그대로 적용할 수 없다. 운영 앱 담당자가 실제 앱 소스와 대조해 연결 지점을 적용해야 한다.

기존 게시판 PR과 별개 기능이다. 운영 사이트 배포, `main` 병합, 기존 공개 Sites 변경은 하지 않았다. 기존 데이터의 삭제·다시 시드·일정 수정도 하지 않았다.

## 검증 방법

Node 22.13 이상과 프로젝트에 지정된 Playwright 브라우저를 사용한다.

```sh
npm ci
npm run check
npm run typecheck
npm run test:notes
npm run test:community
npm run test:notes:browser
npm run build
```

브라우저가 별도 경로에 설치되어 있으면 `PLAYWRIGHT_BROWSERS_PATH`를 그 경로로 지정한다. 브라우저 검사는 `tests/private-notes.html`의 가상 계정으로 실행되며 운영 로그인 코드나 빌드 진입점에 우회를 추가하지 않는다. 실제 MapLibre 엔진을 사용하되 외부 지도 타일 응답은 테스트용 배경으로 대체하므로 스크린샷은 실제 지도 지형 검증 자료가 아니다.

검증 항목: 오프라인 첫 메모 열기·자동 저장·재열람, 같은 장소의 일정 구분, 지도 이동·확대, 계정 전환·로그아웃·보호자 제외, 저장 실패·복구, 삭제·다른 탭 동기화, 일차 전체·장소 없는 일정, 공개 안내판 저장소 접근 차단, 인쇄 숨김, 360/768/1280px·200% 글씨·키보드·모션 감소, 외부 요청에 본문 미포함.

## 서버 연결 시

`usePrivateNotes`를 API 어댑터로 교체하고 서버에서 인증된 고유 사용자 ID를 결정한다. DB에는 `(event_id, user_id, page_key)` 유일 제약을 두며 요청 본문의 `owner`는 신뢰하지 않는다. 조회·수정·삭제는 본인만 허용하고 버전 값을 사용해 동시 수정 충돌을 처리한다. 로그인 계정의 로컬 메모만 미리보기·동의를 거쳐 서버로 옮기고, 다른 계정의 메모를 일괄 업로드하지 않는다. 서버 연결 후에도 게시판 공유는 별도 명시적 동의 기능으로 유지한다.
