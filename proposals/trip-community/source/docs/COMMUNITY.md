# 탐방 이야기 구현과 서버 연결

> 이 문서는 2026-10-11 구현 당시의 앱 구조를 기준으로 합니다. 현재 공개 저장소는 입장 안내용으로 바뀌었으며, 여기의 파일은 검토용 패키지 안에 보관된 구현본입니다. 먼저 [적용 안내](../../README.md)를 읽고 실제 ZUDO 앱에 이식하세요. 현재 앱의 개인 기록 저장 방식·허용 출처·콘텐츠 경로는 협업자가 확인해야 하며, 아래의 GitHub Pages 출처와 기기 저장 설명이 현재 운영 환경에도 그대로 적용된다고 가정하지 않습니다.

## 현재 구현 범위

- 메뉴의 `탐방 이야기`, 장소 안내 아래의 `이 장소의 이야기`.
- 지역·장소·글 유형별 필터와 최신순 목록, 20개 단위 추가 조회.
- 정보 공유·질문·탐방 후기 작성, 제목 100자·본문 10,000자, 사진 최대 5장.
- 계정별 기기 초안, 사진 초안의 IndexedDB 저장, 오프라인 텍스트 작성.
- 본인 글 수정·삭제, 댓글 등록·삭제, 교사의 글 숨김·복구와 댓글 삭제.
- 서버 권한 확인, 동시 수정 충돌 감지, 게시 요청 재전송 중복 방지.
- 숨긴 글과 사진은 학생의 직접 URL 요청으로도 차단.

학생과 인솔 교사만 이용한다. 보호자 공유·익명 글·쪽지·좋아요·자동 개인 기록 공개는 포함하지 않는다.
ZUDO 계정이 없는 비상용 PIN 사용자는 게시판에 접근할 수 없다.
기존 개인 기록은 그대로 기기 저장을 사용하며 게시판 데이터와 섞이지 않는다.

## 서버가 반드시 필요함

GitHub Pages는 화면만 배포한다. 서버 코드를 `main`에 병합하는 것만으로 데이터 저장 기능이 실행되지 않는다.
현재 저장소에는 ZUDO 서버 코드나 배포 권한이 없으므로 운영 서버 연결은 별도 작업이다.
서버 연결 전에는 게시판에 연결 실패 안내가 나오며 초안만 작성할 수 있다. 서버 저장 성공 전에는 게시 완료로 표시하지 않는다.

`server/community/`는 Node.js 22.13 이상에서 실행하는 독립 HTTP 서비스와 Request → Response 처리기를 제공한다.
글·댓글·처리된 사진은 SQLite에 저장한다. 첫 버전에서는 사진까지 같은 DB 트랜잭션으로 저장해 부분 게시와 고아 파일을 방지한다.
배포 플랫폼의 임시 파일 시스템에는 두지 않는다. **영속 볼륨을 연결하거나 기존 ZUDO DB·비공개 파일 저장소에 store 인터페이스를 이식해야 한다.**
오브젝트 저장소로 바꿀 때는 `store.mjs`의 사진 저장·열람·삭제를 교체하고 나머지 API 계약을 유지한다.

## 연결 방법 A: ZUDO와 같은 주소 아래에 배치

1. `server/community`에서 `npm ci`.
2. 환경 변수 `COMMUNITY_DATA_DIR`를 영속 데이터 폴더로 설정한다.
3. `npm start`로 서비스를 시작한다. 기본은 `127.0.0.1:8788`.
4. ZUDO의 HTTPS 프록시에서 `/api/trip/community/`를 이 서비스로 전달한다. Authorization 헤더를 그대로 전달하고 업로드 본문을 16MiB 이하로 제한한다.
5. 서비스는 받은 ZUDO 토큰으로 `https://www.zudo.my/api/trip/me`를 호출해 매 요청마다 자격·역할·만료를 확인한다.
6. `/api/trip/me`는 기존 ZUDO가 처리해야 한다. 게시판 서비스로 다시 보내면 인증이 순환한다.
7. 프론트엔드의 기본 API 주소는 `https://www.zudo.my`이므로 별도 화면 환경 변수는 필요 없다.

같은 프로세스에 넣을 때는 `createHandler({ store, authenticate, catalog, allowedOrigins })`를 호출할 수도 있다.
`authenticate`는 ZUDO의 기존 서버 검증을 사용해 `{ id, name, role: 'student' | 'teacher' }`를 반환해야 한다.
학생의 id는 고정 계정 ID 또는 학번, 교사 id는 고정 계정 ID를 권장한다. 브라우저가 보낸 이름·학번·역할로 정하지 않는다.
기존 데이터베이스를 사용하려면 `store.mjs`의 메서드 계약을 유지하는 어댑터를 만든다. SQLite 버전은 단일 서비스 인스턴스용이다.

## 연결 방법 B: 별도 HTTPS 서버

1. 위 서비스를 영속 볼륨이 있는 서버에 배포한다. 별도 서비스에는 ZUDO의 내부 DB나 명단 복호화 열쇠가 필요 없다.
2. 화면 빌드 환경에 `VITE_COMMUNITY_ORIGIN=https://<게시판 서버 주소>`를 설정한다. Vite가 해당 주소를 CSP의 허용 연결 대상으로 추가한다.
3. 서버의 `COMMUNITY_ALLOWED_ORIGINS`에 `https://shinnanchanguk.github.io`를 설정한다. 와일드카드는 사용하지 않는다.
4. HTTPS 프록시에서 요청 크기 제한과 TLS를 적용한다. DB 파일을 정적 웹 경로에 노출하지 않는다.

서버 환경 변수:

| 변수 | 기본값 / 용도 |
|---|---|
| `HOST` | `127.0.0.1`, 컨테이너에서는 필요에 따라 `0.0.0.0` |
| `PORT` | `8788` |
| `COMMUNITY_DATA_DIR` | `server/community/data`, 운영에서는 영속 볼륨의 절대 경로 |
| `COMMUNITY_ALLOWED_ORIGINS` | `https://shinnanchanguk.github.io`, 여러 주소는 쉼표 구분 |
| `ZUDO_ORIGIN` | `https://www.zudo.my`, 고정된 인증 서버 주소 |

서버 폴더의 `.env`도 `npm start`에서 읽는다. `.env`, DB, 테스트 화면 캡처는 git에서 제외된다.
로컬 검증 시 허용 출처에 `http://127.0.0.1:<Vite 포트>`를 추가한다. 운영에는 로컬 주소를 넣지 않는다.

## API 계약

모든 요청에 ZUDO 기기 토큰 `Authorization: Bearer ...`가 필요하다.
공개 코드·비상용 PIN·기기에 고른 역할은 서버 권한으로 인정하지 않는다.

| 요청 | 내용 |
|---|---|
| `GET /api/trip/community/posts` | `region`, `location`, `kind`, `before`, `hidden` 필터 |
| `POST .../posts` | multipart `payload` JSON + `photos` 0~5장 |
| `GET .../posts/:id` | `{ post, comments }` |
| `PATCH .../posts/:id` | 제목·본문·분류·`version`, 본인만 |
| `DELETE .../posts/:id` | `version`, 본인만, 댓글·사진 함께 삭제 |
| `PATCH .../posts/:id/moderation` | `hidden`, `version`, 교사만 |
| `POST .../posts/:id/comments` | `body`, UUID `clientId` |
| `DELETE .../posts/:id/comments/:id` | 작성자 또는 교사 |
| `GET .../photos/:id` | 권한 확인 후 JPEG 바이트, `no-store` |

글의 `clientId`는 기기 초안의 UUID다. 같은 요청을 다시 보내면 기존 글을 반환한다.
같은 UUID로 내용이나 사진을 바꾸어 다시 보내면 409로 거부한다. 응답이 유실된 뒤 수정한 초안을 성공으로 잘못 처리하지 않는다.
`version`이 오래됐으면 409를 반환하고 수정 내용을 덮어쓰지 않는다.
사진은 화면에서 1600px JPEG로 줄인 뒤 보내고 서버에서도 매직 바이트·픽셀 수를 검사해 다시 처리한다. EXIF·GPS는 유지하지 않는다.
사진 URL은 공개 주소가 아니다. 화면에서 토큰으로 받아 Blob URL을 만들고 화면을 닫으면 해제한다. 서비스 워커에도 저장하지 않는다.
숨김·복구·삭제는 DB의 audit 표에 기록한다. 일반 로그에는 글 본문, 사진, 토큰을 출력하지 않는다.

## 운영과 검증

- Node.js의 SQLite backup API 또는 서비스를 멈춘 상태의 SQLite 백업으로 복구 가능한 사본을 보관한다. 실행 중 `community.sqlite` 파일만 복사하지 않는다(WAL 파일에 최신 데이터가 있을 수 있다).
- 사진도 DB에 포함되므로 DB 백업·삭제 정책에 함께 포함된다. 행사 종료 후 학교의 보관 기간을 정해 정리한다.
- 새 행사나 다중 서버 운영으로 확장할 때는 데이터베이스 어댑터와 행사별 참가자 권한을 추가한다.
- ZUDO 기기 토큰의 행사 후 만료 정책을 그대로 따른다. 만료 이후 열람을 원하면 ZUDO 세션 정책도 함께 검토해야 한다.

검사 명령:

```sh
npm run check
npm run typecheck
npm run test:community
npx playwright install chromium
npm run test:community:browser
npm run build
```

브라우저 검사는 테스트 화면과 가상 계정으로 실제 게시판 API 처리기·SQLite를 사용한다. 운영 로그인이나 명단 복호화를 우회하는 코드는 배포 엔트리에 넣지 않는다.
운영 연결 뒤에는 실제 학생 두 계정과 교사 계정으로 다른 기기 간 글·댓글 반영, 권한, 숨김, 사진 열람을 확인한 다음 개통한다.

### 로컬 확인 결과 (2026-10-11)

- 서버 통합 검사 16개 통과: 인증·역할·소유권, 사진 검사·EXIF 제거, 숨김 접근 차단, 재전송·충돌, 크기 제한, 서버 재시작 후 보존.
- 실제 화면 → API 처리기 → SQLite 흐름 통과: 글·사진·댓글·수정, 초안 재열람, 오프라인, 두 기기 역할별 숨김 반영.
- 360/768/1280px, 200% 글자 확대, 키보드 초점, 모션 감소 환경 검사.
- 기존 콘텐츠 검사·TypeScript·본 사이트/공개 안내판 빌드와 공개 안내판 개인정보 검사 통과.

이는 가상 계정을 사용한 로컬 검증이다. 운영 서버 배포·실제 ZUDO 계정 연동 완료를 뜻하지 않는다.
