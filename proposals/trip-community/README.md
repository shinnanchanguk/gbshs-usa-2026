# 탐방 이야기 게시판 검토안

현재 저장소의 입장 안내 페이지를 바꾸지 않고, 게시판 구현본을 협업자에게 전달하기 위한 검토안입니다. 이 폴더를 병합해도 게시판이 운영 사이트에 자동으로 추가되지는 않습니다.

## 포함한 기능

- 지역·장소별 정보 공유, 질문, 탐방 후기와 필터, 목록 추가 조회
- 글 작성, 사진 최대 5장, 댓글, 본인 글의 제목·본문·분류 수정과 삭제
- 계정별 기기 초안과 사진 초안 저장, 오프라인 텍스트 작성
- 교사의 글 숨김·복구와 댓글 삭제
- 서버의 로그인·역할·작성자 확인, 동시 수정 충돌과 중복 게시 방지
- 사진 형식·크기 검사, JPEG 재처리, EXIF·GPS 제거, 숨긴 사진 접근 차단

학생과 인솔 교사가 사용합니다. 보호자 공유, 익명 글, 쪽지, 좋아요는 첫 구현 범위에 포함하지 않았습니다. 기존 개인 기록을 게시판에 자동으로 공개하지 않습니다.

## 파일 구성

- `source/`: 게시판 구현 때 새로 추가한 서버, 화면, 테스트, 지역 카탈로그, 연결 문서. 실제 앱의 대응 경로로 옮겨서 사용합니다.
- `integration.patch`: 기존 앱 파일을 수정한 부분만 담았습니다. 메뉴·화면 진입점, 초안 저장, 모바일 스타일, 비공개 API 캐시 제외, 서버 주소 설정과 필요한 개발 의존성을 연결합니다.
- `CHANGES.md`: 변경 사항, 검증 결과, 협업자가 확인할 항목.

원본 구현은 `9686d7dd2538df6d17eb4013b4608089bfc187a7`을 기준으로 작성됐고, 구현 완료 커밋은 `c7fa94aa7f06f75a7b17cd315d2dd751cc4acd48`입니다. 원격 저장소가 입장 안내용으로 바뀌어 기존 PR과 기능 브랜치가 없어졌으므로, 현재 main에서 새 검토 브랜치를 만들었습니다.

이전 안내 자료, 사진, 명단 암호문, 객실·좌석 데이터, 로그인 코드·토큰, 실제 학생의 글·사진은 다시 올리지 않았습니다. 시간표에서 발견한 표시 문제의 수정도 이 검토안에는 포함하지 않습니다.

## 적용 순서

1. 현재 ZUDO의 실제 체험학습 앱 소스에서 별도 기능 브랜치를 만듭니다.
2. `source/`의 파일을 앱의 대응 경로로 옮깁니다. 현재 앱에 같은 기능이나 파일이 있으면 내용을 비교해 반영합니다.
3. `integration.patch`를 검토합니다. 앱이 그 이후 바뀌었으므로, 먼저 `git apply --check <패치의 절대 경로>`로 확인하고 충돌하면 수동으로 이식합니다. 이 입장 안내 저장소에는 적용하지 않습니다.
4. 기존 지역·장소 ID와 `source/content/community.json`을 맞춥니다. 서버의 기본 카탈로그는 실제 앱의 `content/days/`를 읽으므로, 이 검토안만으로 운영 서버를 바로 시작할 수는 없습니다. 다른 콘텐츠 체계를 쓰면 `catalog.mjs`를 맞추거나 `createHandler`에 검증된 카탈로그를 주입합니다.
5. 협업자가 기존 DB에 맞는 저장 어댑터를 만들거나, SQLite 단일 서비스와 영속 저장 공간을 배포합니다.
6. 실제 앱 출처를 서버의 허용 출처에 등록하고, HTTPS API 주소와 실제 ZUDO 로그인 검증을 연결합니다. 이전 GitHub Pages 출처를 운영 기본값으로 그대로 쓰지 않습니다.
7. 실제 학생 두 계정과 교사 계정으로 공동 사용·권한·사진·재시작 후 보존을 확인합니다.

세부 API와 저장 방식은 [서버 연결 안내](source/docs/COMMUNITY.md)에 있습니다.

## 이 검토안에서 실행할 수 있는 검사

Node.js 22.13 이상이 필요합니다. 저장소 루트에서 다음 검사를 실행할 수 있습니다.

```sh
npm ci --prefix proposals/trip-community/source/server/community
npm test --prefix proposals/trip-community/source/server/community
```

서버 통합 검사는 가상 계정과 테스트용 카탈로그를 사용합니다. 실제 ZUDO 계정이나 운영 DB에 접근하지 않습니다. 화면 검사와 전체 빌드는 실제 앱으로 이식한 후 실행해야 합니다. 이전 구현의 화면 검사 코드는 `source/tests/`에 포함했습니다.

main 병합, 운영 배포, 실제 DB 변경은 이 작업에서 하지 않습니다.
